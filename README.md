# C++ GameDev Journey

Упражнения и заметки по изучению C++ и разработке игр.

## Что установлено

Для работы используются VS Code, Apple Clang с поддержкой C++20, CMake, Git и отладчик LLDB. В VS Code установлены расширения C/C++, CMake Tools и CodeLLDB.

## Структура

- `exercises/` — практические задания.
- `notes/` — конспекты и полезные материалы.
- `CMakeLists.txt` — настройки сборки упражнений.
- `build/` — создаётся при сборке и не сохраняется в Git.

## Упражнение 1. Hello, C++

Файл: `exercises/01-hello-cpp/main.cpp`.

Программа выводит приветствие. В ней `#include <iostream>` подключает средства ввода и вывода, `main()` — точка входа в программу, а `std::cout` выводит текст в терминал. `\n` переносит строку, а `return 0` сообщает об успешном завершении.

### Сборка и запуск

В VS Code откройте терминал через **Terminal → New Terminal** и выполните команды из корневой папки проекта:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
./build/hello_cpp
```

Ожидаемый результат:

```text
Hello, game developer!
```

Первая команда подготавливает сборку в папке `build`, вторая компилирует программу, третья запускает её. После изменения кода повторите две последние команды.

### Отладка в VS Code

1. Откройте `exercises/01-hello-cpp/main.cpp`.
2. Нажмите слева от номера строки с `std::cout`, чтобы поставить красную точку останова.
3. Откройте палитру команд (**Cmd+Shift+P**) и выполните **CMake: Debug**. Если VS Code попросит выбрать цель, выберите `hello_cpp`; если попросит компилятор, выберите Apple Clang.
4. Когда программа остановится, используйте кнопки отладчика для пошагового выполнения или продолжения.

## Debug и Release

**Debug** — режим для разработки и поиска ошибок. Обычно он включает отладочную информацию и мало оптимизирует код, поэтому удобнее выполнять программу по строкам и изучать переменные.

**Release** — режим для готовой программы. Компилятор применяет оптимизации, чтобы программа работала эффективнее. Из-за них некоторые переменные могут исчезнуть, а порядок инструкций отличаться от исходного кода, поэтому отлаживать программу сложнее.

### Отладочные символы

Отладочная информация связывает машинный код с исходными файлами, строками и переменными. Она помогает отладчику LLDB показать, где остановилась программа. Наличие символов само по себе не означает отсутствие оптимизаций: эти настройки можно комбинировать.

### Оптимизации

Оптимизации — преобразования компилятора, которые сохраняют предусмотренное программой поведение и помогают ей работать быстрее или занимать меньше места. Например, компилятор может вычислить заранее выражение с постоянными значениями или удалить неиспользуемый результат. Оптимизированный код сложнее сопоставить с исходными строками.

### Как собрать оба варианта

Используйте отдельные папки сборки, чтобы варианты не смешивались:

```bash
cmake -S . -B build/debug -DCMAKE_BUILD_TYPE=Debug
cmake --build build/debug
./build/debug/hello_cpp

cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release
cmake --build build/release
./build/release/hello_cpp
```

Обе версии должны вывести одинаковое приветствие. Для учебных упражнений и отладки начинайте с Debug; Release пригодится для проверки производительности и готовых сборок.

## Что такое Blueprint

Blueprint — система визуального программирования в Unreal Engine. Логика создаётся в редакторе из соединённых узлов: события, условия, действия и значения изображаются блоками и связями между ними.

Например: событие «игрок вошёл в область» → проверка «есть ли ключ» → действие «открыть дверь». Blueprint можно использовать для поведения объектов, интерфейса и игровых правил.

Blueprint и C++ дополняют друг друга: общую логику можно написать на C++, а настройки и конкретные реакции создавать в Blueprint. Начинать можно с любого из них; использование Blueprint не требует отказа от изучения C++.

## Как устроен C++-проект

- `.h` и `.hpp` — заголовочные файлы. Обычно в них помещают объявления: какие функции, типы и классы доступны другим файлам. Оба расширения используются в C++; единого обязательного различия между ними нет.
- `.cpp` — файлы исходного кода. Обычно в них находятся определения функций и другая реализация. Каждый `.cpp` обычно компилируется отдельно в объектный файл.
- Библиотека — переиспользуемый код, который подключают к программе. Заголовки предоставляют объявления, а скомпилированная библиотека может содержать реализацию. Бывают статические и динамические библиотеки; некоторые библиотеки целиком состоят из заголовков.
- Include paths — папки поиска заголовков. По ним препроцессор ищет файлы из директив `#include`; подключение заголовка само по себе не заменяет линковку нужной скомпилированной библиотеки.

В нашем упражнении `main.cpp` подключает стандартный заголовок `<iostream>` и использует `std::cout`. CMake описывает цель `hello_cpp`, а компилятор и линкер собирают программу.

## Упражнение 2. Предупреждения компилятора

Предупреждение (`warning`) обращает внимание на потенциальную проблему, но обычно не останавливает сборку. Ошибка (`error`) останавливает сборку. Предупреждения не гарантируют обнаружение всех ошибок.

В `CMakeLists.txt` для каждой учебной программы включены:

- **Clang и GCC:** `-Wall` включает широкий набор предупреждений, `-Wextra` добавляет другие проверки, `-Wpedantic` сообщает о некоторых нарушениях и расширениях относительно выбранного стандарта C++. Несмотря на название, `-Wall` включает не все предупреждения.
- **MSVC:** `/W4` включает высокий уровень предупреждений, а `/permissive-` включает более строгий режим соответствия стандарту. Это приблизительно похожие настройки, а не точный эквивалент флагов Clang/GCC.

### Практика

1. Откройте `exercises/02-warnings/main.cpp`. В программе есть переменная `player_score`, которая пока не используется.
2. В терминале VS Code из корня проекта выполните:

   ```bash
   cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
   cmake --build build --target warnings_practice
   ./build/warnings_practice
   ```

3. При компиляции Clang должен показать предупреждение `unused variable 'player_score'` и указать строку. Сборка при этом должна завершиться успешно, а программа — вывести здоровье игрока.
4. Исправьте причину предупреждения: выведите счёт игрока с помощью `std::cout`, как уже выводится здоровье. Затем повторите команду сборки и запуск. Предупреждение об этой переменной должно исчезнуть, а программа должна показать здоровье и счёт.

Если сборка сообщает, что цель уже собрана, она не перекомпилирует неизменённый файл и предупреждение повторно не появится. Чтобы увидеть его снова до исправления, выполните `cmake --build build --target warnings_practice --clean-first`.

Дополнительно: `-Werror` в Clang/GCC и `/WX` в MSVC превращают предупреждения в ошибки. Мы пока их не включаем, чтобы видеть разницу между предупреждением и ошибкой.

## Упражнение 3. Основы CMake

**Target (цель)** — объект сборки, которым управляет CMake. Целью может быть программа или библиотека; у неё есть свои исходные файлы, настройки и зависимости.

- `add_executable(score_game ...)` создаёт цель для исполняемой программы.
- `add_library(score_library ...)` создаёт цель для библиотеки с переиспользуемым кодом. Тип библиотеки без явного указания зависит от настройки CMake `BUILD_SHARED_LIBS`.
- `target_link_libraries(score_game PRIVATE score_library)` связывает программу с библиотекой. `PRIVATE` означает, что зависимость нужна самой цели и не передаётся дальше как её публичная зависимость.
- `target_include_directories(score_library PUBLIC exercises/03-cmake)` задаёт путь к заголовкам библиотеки и передаёт его целям, которые её используют.
- `enable_testing()` включает тестирование, а `add_test(...)` регистрирует тест для CTest. Тестовая программа возвращает `0` при успехе и ненулевой код при ошибке.

В `exercises/03-cmake/` лежат библиотека `score.hpp` / `score.cpp`, использующая её программа `main.cpp` и тест `score_test.cpp`. Для сборки, запуска и проверки в терминале VS Code:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
./build/score_game
ctest --test-dir build --output-on-failure
```

Программа выводит `Счёт: 125`, а CTest сообщает об успешном тесте. Сначала запускайте сборку: CTest сам не компилирует тесты.
